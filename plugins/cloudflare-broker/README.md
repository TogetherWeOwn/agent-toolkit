# Cloudflare provider package — incomplete source build

This directory is an interface-first provider lane, **not an installable plugin or live credential broker**. There is no worker, credential resolver, tool registration or authorization implementation. Internal bounded readers and an initial source binding to the reviewed `toolkit.provider-broker/v1` executor are available, not exposed as tools. Source work cannot authorize a Cloudflare call. Actual host integration, remaining API/tier coverage and provider qualification remain incomplete.

## Coverage ledger

`coverage/source.json` pins the official Cloudflare OpenAPI file by revision, version and exact-byte SHA-256. `coverage/operations.jsonl` retains every method/path in that schema, including deprecated and SDK-ignored operations. It records original API areas, permission/token-group/security/plan annotations, parameter names, request/response-shape fingerprints, typed descriptor association, tier, authority route and implementation/review/enablement state. Shape fingerprints reference the pinned schema; they are not substitute input validators. No generated row is a callable tool or grant.

The initial universe contains 3,777 operations on 2,352 paths across 599 API tags. **All credential entitlements are unknown.** Thirty-three operations have typed metadata descriptors, one has a current-content digest descriptor and five have reserved deletion-plan descriptors; zero are integrated tools, reviewed, enabled or package-complete. The other 3,738 operations remain explicitly missing and unclassified. The content row uses `implementation: content-descriptor-only`, not metadata-only or an implemented source reader. Plan-only rows use `implementation: plan-descriptor-only` and retain execution/projection, provider-precondition and native-authority prerequisites; they are not implemented destructive tools. Unknown tier/authority/scope, a deny-all placeholder or a descriptor alone never counts as implemented. Counts describe the pinned OpenAPI universe, not the actual credential intersection or every Cloudflare protocol. The supplemental `coverage/r2-s3.json` retains 73 documented S3 operations (26 provider-supported, 47 unsupported), feature restrictions, region/checksum tables and behavioral limitations at a separately pinned official docs revision. All 73 remain missing/unclassified/unreviewed/disabled in this package, with unknown credential compatibility and explicit owning prerequisites; an unsupported provider operation is not a completed adapter. S3 counts are separate from the REST OpenAPI counts. GraphQL's exact entitled dataset/field schema remains uninventoried; reference examples are not a schema. Additional surfaces discovered during scope attestation must be added, not dropped.

Operator scope attestation must contain metadata only: credential reference/type, validity, accounts/zones/resource restrictions, permissions and plan entitlements. API annotations are requirements, not proof of entitlement. Private connection/credential references and attestation evidence stay in the private admission record, not this public source manifest. Connection metadata alone does not establish live provider validity, the complete account/zone membership, current plans or operation/protocol entitlement. OAuth scopes, API-token permission groups and S3 signing credentials are distinct; do not infer one from another. Do not retrieve raw credentials to perform inventory, mint a token, broaden access or bypass a 403.

A broker-held master credential is intentional: its scope count/breadth alone is not a defect and does not require rotation, narrowing or re-consent. Credential capability is an upper bound, never an agent grant. The broker must enforce current per-agent AND operation/account/zone/resource policy tiers before any request; existing protected-action denials remain until the actual decider approves a change. This design does not waive secret exposure, policy bypass, shared-UID limitations, exact production/credential/spend authority, independent reviews or installation/enablement gates. No automatic per-call credential minting is permitted; where supported and separately authorized it may be added, otherwise broker-side scoping and its residual boundary must be documented.

## Initial reviewed-core source binding — not host qualification

`src/read-operations.ts` binds all thirty-three existing metadata descriptors plus the separately source-allowlisted current-content digest to the reviewed core v1 `ProviderOperation` interface. It is an internal typed registry, not a generic HTTP executor, tool callback or enabled broker. The reviewed core dependency is reused without changes to its executor.

`CloudflareReadScope` adds independent `secretStores`, `durableNamespaces` and `pagesProjects` allowlists, each defaulting empty and copied by its descriptor factory. There are 29 source operations without a zone and 34 with one. Account and revision always come from the common scope, never a nested override. These are construction snapshots only: the accepted native host must establish the zone relationship and revalidate the exact account/zone/resource revision before credentials and after awaited steps. A filtered or empty list still requires pre-request current agent AND resource policy; empty output is not a substitute for authorization.

Each preparation binds the exact resource/revision, validated arguments and fixed bounded request plan; the plan explicitly establishes neither a provider dry-run nor a provider revision fence. Execution reconstructs and compares the complete preparation, then uses the existing one-GET transport and descriptor projection. Each response gets a private one-use opaque receipt for core `project(raw)`, avoiding mutable shared request state across concurrent calls. Metadata operations use the core read tier. ## Current Worker content — separate source authorization, no live reader

`src/current-content.ts` describes the supported `worker-script-get-content` operation, `GET /accounts/{account_id}/workers/scripts/{script_name}/content/v2`. It accepts only a script name from a separately copied `sourceDigestScriptNames` allowlist (empty by default); ordinary metadata/control/version access is not source authorization. It accepts no version, deployment, URL, account or historical selector. The endpoint returns **current** content, not historical or version-pinned source. Lack of a source SHA in version metadata is not evidence that current content retrieval is unsupported.

The pure projection hashes at most 128 KiB of nonempty response-body bytes and returns only SHA-256, byte length, script identity and explicit limitations. `digest.subject: captured-response-body` is not a provider source/build SHA, canonical bundle/module digest, embedded-library inventory or historical binding. For example, multipart boundary changes alter this digest without changing module contents. There is no multipart parser or source output, and module attribution/library versions remain unavailable. Prepared inputs must originate from the same descriptor instance; that local binding is not native authorization, freshness, replay protection or authenticated provider provenance.

`currentContentTransport` in `src/metadata-transport.ts` now supplies an **internal, unqualified digest reader**, sharing the metadata transport's fixed-origin GET, status/provenance checks, streaming byte/chunk cap, deadline, cancellation and late-response cleanup. It accepts only the exact current-content path, never a version query or other metadata endpoint. The pinned schema's success content key is literally `string`, not a usable media-type contract. The local contract deliberately supports only `multipart/form-data` with one restricted 1–70-character boundary parameter and matching opening/closing framing; unsupported formats, JSON/HTML error bodies, ambiguous parameters, mismatched framing and epilogues refuse. This is a narrow local subset, not a claim to support every provider response. Inner parts are **not parsed or semantically validated**; a framing-valid body is still only a captured-response checksum, not validated module/source identity. Binary bytes are hashed directly, without text decoding. JSON-only metadata projection is never used for content.

Successful transport results add an immutable `capture`: a locally generated UUID correlation ID, start/end wall-clock timestamps, monotonic duration, prepared resource/revision, `format: multipart-form-data-framing-only` and `provenance: internal-transport-observation`. The local window covers fetch and body collection; backward wall-clock movement, cancellation and an elapsed deadline refuse. Values never come from model arguments or provider headers. Neither the UUID nor these timestamps are native audit receipts, provider attestations, deployed-version bindings or proof that policy/credential authority remained current. Reviewed-core correlation, current source-policy revalidation, credential-safe output/audit/journal integration, actual media qualification and native refusal fixtures remain required. The coverage prerequisites retain these gaps; internal transport alone does not upgrade any row to integrated/reviewed/enabled.

Module-level digests/library extraction need a separately reviewed bounded parser/projection. The schema's SDK-deprecation annotation does not prove provider non-support. Reuse an already supported native read where its approved agent/resource/source policy suffices; this source descriptor does not install, register, enable or replace it. Current capture cannot prove which historical deployment served traffic; that requires independent matching evidence, never a synthesized SHA or version relationship. `test/cloudflare-current-content.test.mjs` adds synthetic-network fixtures only, including binary exact-byte capture, media/framing refusal, error sanitization, byte/chunk limits, cancellation and late-result cleanup; there is no live credential or provider call.
