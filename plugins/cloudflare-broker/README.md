# Cloudflare provider package — incomplete source build

This directory is an interface-first provider lane, **not an installable plugin or live credential broker**. There is no worker, credential resolver, tool registration or authorization implementation. Internal bounded readers and an initial source binding to the reviewed `toolkit.provider-broker/v1` executor are available, not exposed as tools. Source work cannot authorize a Cloudflare call. Actual host integration, remaining API/tier coverage and provider qualification remain incomplete.

## Coverage ledger

`coverage/source.json` pins the official Cloudflare OpenAPI file by revision, version and exact-byte SHA-256. `coverage/operations.jsonl` retains every method/path in that schema, including deprecated and SDK-ignored operations. It records original API areas, permission/token-group/security/plan annotations, parameter names, request/response-shape fingerprints, typed descriptor association, tier, authority route and implementation/review/enablement state. Shape fingerprints reference the pinned schema; they are not substitute input validators. No generated row is a callable tool or grant.

The initial universe contains 3,777 operations on 2,352 paths across 599 API tags. **All credential entitlements are unknown.** Seventy-eight operations have typed metadata descriptors, one has a current-content digest descriptor and five have reserved deletion-plan descriptors; zero are integrated tools, reviewed, enabled or package-complete. The other 3,693 operations remain explicitly missing and unclassified. The single-zone-setting descriptor covers only ten TLS/HTTPS variants; its ledger row marks variant coverage incomplete and names the remaining-variant prerequisite. The content row uses `implementation: content-descriptor-only`, not metadata-only or an implemented source reader. Plan-only rows use `implementation: plan-descriptor-only` and retain execution/projection, provider-precondition and native-authority prerequisites; they are not implemented destructive tools. Unknown tier/authority/scope, a deny-all placeholder or a descriptor alone never counts as implemented. Counts describe the pinned OpenAPI universe, not the actual credential intersection or every Cloudflare protocol. The supplemental `coverage/r2-s3.json` retains 73 documented S3 operations (26 provider-supported, 47 unsupported), feature restrictions, region/checksum tables and behavioral limitations at a separately pinned official docs revision. All 73 remain missing/unclassified/unreviewed/disabled in this package, with unknown credential compatibility and explicit owning prerequisites; an unsupported provider operation is not a completed adapter. S3 counts are separate from the REST OpenAPI counts. GraphQL's exact entitled dataset/field schema remains uninventoried; reference examples are not a schema. Additional surfaces discovered during scope attestation must be added, not dropped.

Operator scope attestation must contain metadata only: credential reference/type, validity, accounts/zones/resource restrictions, permissions and plan entitlements. API annotations are requirements, not proof of entitlement. Private connection/credential references and attestation evidence stay in the private admission record, not this public source manifest. Connection metadata alone does not establish live provider validity, the complete account/zone membership, current plans or operation/protocol entitlement. OAuth scopes, API-token permission groups and S3 signing credentials are distinct; do not infer one from another. Do not retrieve raw credentials to perform inventory, mint a token, broaden access or bypass a 403.

A broker-held master credential is intentional: its scope count/breadth alone is not a defect and does not require rotation, narrowing or re-consent. Credential capability is an upper bound, never an agent grant. The broker must enforce current per-agent AND operation/account/zone/resource policy tiers before any request; existing protected-action denials remain until the actual decider approves a change. This design does not waive secret exposure, policy bypass, shared-UID limitations, exact production/credential/spend authority, independent reviews or installation/enablement gates. No automatic per-call credential minting is permitted; where supported and separately authorized it may be added, otherwise broker-side scoping and its residual boundary must be documented.

To reproduce (schema data and scripts remain in separate directories):

```sh
schema_dir=$(mktemp -d)
curl -fsS --max-time 120 --max-filesize 60000000 \
  https://raw.githubusercontent.com/cloudflare/api-schemas/650bd71c22db3b938a4611bf4cc5afd896b400b7/openapi.json \
  -o "$schema_dir/openapi.json"
node plugins/cloudflare-broker/scripts/inventory.mjs "$schema_dir/openapi.json" "$schema_dir/operations.jsonl"
cmp plugins/cloudflare-broker/coverage/operations.jsonl "$schema_dir/operations.jsonl"
```

The generator verifies the full source hash before JSON parsing and fails on unexpected source/descriptor identity. CI reproduces the entire map from the pinned official file. Run tests/builds through GitHub Actions; there is no need to install dependencies locally for this slice.

`coverage/families.json` is a reproducible source-workload rollup, generated with `node plugins/cloudflare-broker/scripts/families.mjs <operations.jsonl> <families.json>`. It assigns each operation once to its **first provider tag**: 596 primary families, 599 distinct tags and six multi-tagged operations. Secondary tags remain visible; do not sum overlapping tag memberships as operations. Each family retains method counts, resource-parameter names, distinct unresolved shape fingerprints, missing/unclassified counts and source-only coverage. Methods are **not** policy tiers (GET can expose secrets; POST can read). Fingerprint counts are not resolved-schema equivalence or reusable adapter counts. This summary excludes supplemental protocols and is neither a credential intersection nor an active/wait P50/P90 forecast. Bottom-up estimates still require entitlement, schema/authority complexity and qualified capacity evidence; descriptor throughput is not a complete-package delivery estimate. CI independently regenerates this rollup from the pinned-source operation inventory.

Names, source, rows, schema, timestamps, file size, running region and the provider-deprecated inaccurate table count never return. No SQL, replication mutation, credential lookup, provider call, installation or enabled tool is introduced.
