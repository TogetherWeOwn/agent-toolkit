# Cloudflare Read Broker

Paperclip plugin; agents never receive the Cloudflare OAuth access token. Configure a company-scoped instance with closed JSON:
```json
{"accountId":"0123456789abcdef0123456789abcdef","apiTokenSecretRef":{"type":"secret_ref","secretId":"secret-id"},"policy":{"version":1,"companyId":"company-id","revision":1,"agents":[{"agentId":"agent-id","profile":"read","workerScripts":["my-worker"],"containerApplicationIds":["application-id"]}]}}
```
Unknown agents, `none`, other companies and unlisted resources fail before secret access. Identity comes only from the authenticated Paperclip tool gateway, never tool arguments. Policies also inherit core's 16 KiB/256-node JSON bounds. No refresh token exchange or credential fallback.

Tools (prefix `cloudflare.`): `workers.listDeployments {script}`, `workers.getVersion {script,versionId}`, `workers.queryLogs {script,from,to,limit,filter?}`, `containers.getApplication {applicationId}`, `containers.listRollouts {applicationId}`. Log timestamps are Unix **milliseconds**, window ≤24h within the last 7 days, limit 1–100, filter a case-sensitive literal contains search. Log output retains timestamp and metadata id/level/message/error, not raw payloads. Lists return at most 100 entries; no automatic pagination.

Official API paths checked 2026-11-13: [deployments](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/subresources/deployments/methods/list/), [version](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/subresources/versions/methods/get/), [telemetry](https://developers.cloudflare.com/api/resources/workers/subresources/observability/subresources/telemetry/methods/query/), [application](https://developers.cloudflare.com/api/resources/containers/subresources/applications/methods/get/). Version `created_on` comes from `metadata.created_on`; only workers/message and workers/tag annotations are retained when present.
**Rollouts unsupported:** [official rollouts docs](https://developers.cloudflare.com/api/resources/containers/subresources/applications/subresources/rollouts/) expose only POST/create, no GET/list. This tool returns `cloudflare.rollouts_unsupported` without resolving the secret or making any request; it does not pretend application versions are rollout history.

Threat notes: fixed `https://api.cloudflare.com/client/v4` origin and validated path segments, GET only except fixed-body telemetry POST with `dry:true`, inline parameters and mandatory script equality filter (requires Cloudflare's “Workers Observability Write” permission despite being a read). No caller URL, headers, raw query, redirects, retries or error bodies/headers. Project first, then redact the exact token, emails and common secret-looking strings; heuristics are not a general log DLP guarantee. Treat returned log text as untrusted data.
Transport uses native `ctx.http.fetch`: the SDK drops redirect/signal, so host ≥2026.1106.0's single pinned request/no-follow, 200 MiB transport cap and 30s native request deadline are required. The plugin additionally enforces 256 KiB before JSON parsing, a 30s caller deadline and four unsettled operations; timeout is not cancellation. Source contracts: `@paperclipai/server/dist/services/plugin-host-services.js`, `server/dist/routes/plugins.js`, `plugin-sdk/dist/worker-rpc-host.js`. Audit records contain only operation, gateway agent/run and policy revision, not inputs or outputs.

Add a tool only when needed: verify official docs; explicitly authorize its operation/resource; project output; prove denial-before-secret, fixed transport and credential hygiene with fake-fetch tests. Never add raw HTTP or write passthrough. Root `npm test` already builds/tests this workspace; no new host automation or workflow is needed. Build/test with `npm run build -w plugins/cloudflare-broker && npm test -w plugins/cloudflare-broker`.
