# Offline audit substrate

This unregistered test-only substrate models admission using a local SQLite journal. It has no reader, provider integration, credentials, installation or network access. It is a narrower replacement informed by the retained offline preference-audit fixture in PR #47 (head `ebed45299e9563a951ae513465a870c750c2a201`, authored by Rick7C2); that draft and its source workspace are preserved.

Admission and refusal records are committed before invoking a synthetic operation. An unresolved record blocks every later admission. Opening another owner converts pending records to permanent unknown records, fencing any earlier owner from publishing success. A timed-out, cancelled, failed or interrupted operation leaves a pending record that becomes unknown upon reopening; there is no recovery, reconciliation, deletion or unknown-clearing API. A successful synthetic operation requires both fake promises to settle and its final audit write to succeed. Late promise resolution cannot publish a result. Records contain only a random ID and fixed outcome; the returned fixture value is not stored.

SQLite's durability depends on its filesystem honoring synchronization. This design assumes all owners use the same intact database file and no actor modifies it outside this API; a copied, replaced or corrupt journal is not fenced. No fixture promise or timeout proves real provider session closure. No target, ACL, TLS, identity, expiry, fixed reader, projection, production audit retention, external fencing or provider closure guarantee is implemented. These remain independent integration and Security obligations. Never install or enable this fixture as a provider tool.
