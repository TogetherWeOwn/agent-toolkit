# Offline preference audit and closure fixture

This source-only fixture is not an installed tool or a production audit service. It stores a generated correlation ID, fixed outcome and closure state in SQLite with WAL and FULL synchronization. No arguments, results, provider errors, credentials or remote identifiers are persisted. A durable pending/unknown record is created before the adapter is called. If that write fails, the adapter is not invoked; if finalization fails, the caller gets unavailable and the pending record remains for reconciliation. SQLite durability is conditional on the filesystem and storage implementation honoring sync.

The adapter supplies an explicit closure acknowledgement. A timeout, cancellation, failure or restart cannot promote an in-flight or interrupted read to confirmed closure: the read must have settled before closure begins, and closure must explicitly acknowledge within its separate bounded deadline. Cancellation does not suppress the cleanup attempt, and no result is returned if cancellation was observed. Operations ignoring abort may continue after the caller returns; unknown is a recovery obligation, not proof of remote state. No blind retry or automatic cleanup is provided.

Admission uses a SQLite immediate transaction to permit at most one outstanding pending or failed/unknown call per shared database. A rejected admission gets a separate redacted refusal record and never invokes its adapter. An interrupted pending or failed/unknown call continues to occupy the slot across reopen; this fixture intentionally offers no automatic release or reconciliation. Confirmed closure releases the slot. This is a conservative local admission limit, not a bound on work outside this database or a substitute for provider-side limits. The generated ID correlates records only; it is not authenticated caller identity.

This fixture does not enforce identity, target, ACL, transport security, query scope, result projection, audit retention or access control. Its adapter and store are test-only, and a reopen test is not a process-crash or power-loss test and cannot establish a provider's closure semantics, remote transaction cancellation, production crash durability, deployment governance or recovery scheduling. Integration must define and independently verify those contracts, supply authenticated audit identity, production-grade trusted audit storage and reconciliation before any install or enablement. Local fake-adapter evidence cannot substitute for Security acceptance.
